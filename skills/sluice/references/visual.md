# Visual companion

Offer this just-in-time, never upfront. Hold off until some question in
the conversation actually turns on what something looks like rather than
what it means, then offer it as its own message and wait. If that moment
never arrives, never offer it.

Run this check on every question, not once at the start: could you settle
it in a sentence, or does it need the options side by side to look at? A
question can be about the interface and still belong to the first group.
"Should deleting a record ask for confirmation first?" is a policy call,
argue it in words. "Should the confirm button be red and set apart, or
match the row it belongs to?" needs looking at, so show it.

The line runs through appearance, not subject matter. A screen layout, a
colour pairing, a diagram of how pieces connect: show it. A decision you
could write as a sentence, what's in scope, which architecture to use,
what a term means: say it.

Delivery: write the page to a file and publish it with the `Artifact` tool.
To iterate, edit the same file and republish it; the URL stays the same. If
`artifact-design` or `artifact-diagramming` guidance is available, follow
it instead of restating page-design rules here.

Cap each page at a small handful of options, and put the question on the
page itself, not only in chat. Match fidelity to what's being decided:
quick and rough while the shape is in question, filled in once that's
settled.

Feedback stays in chat. The page shows options; it does not collect answers.

If `Artifact` is unavailable, write a self-contained HTML file instead and
hand your partner the path.
