# Visual companion

Offer this just-in-time, never upfront. Wait until a question would
genuinely be clearer shown than described, then offer it as its own message
and wait. If no such question comes up, never offer it.

Apply this test to every question, not once per session: would they
understand this faster by seeing it than reading it? A question merely about
a UI topic is not automatically visual. "What should personality mean here?"
is conceptual: use text. "Which of these two layouts?" is visual: show it.

Visual: mockups, wireframes, layout and colour comparisons, architecture
diagrams, state machines, anything spatial. Text: requirements, scope,
tradeoff lists, choices spelled out in words, technical decisions that do
not turn on appearance.

Delivery: write the page to a file and publish it with the `Artifact` tool.
There is no server, port, or process to run. To iterate, edit the same file
and republish it; the URL stays the same. If `artifact-design` or
`artifact-diagramming` guidance is available, follow it instead of
restating page-design rules here.

Show two to four options per screen, and put the question on the page
itself, not only in chat. Match fidelity to the question: rough wireframes
for a layout choice, real detail only when the question is actually about
polish.

Feedback stays in chat. The page shows options; it does not collect answers.

If `Artifact` is unavailable, write a self-contained HTML file instead and
hand your partner the path.
