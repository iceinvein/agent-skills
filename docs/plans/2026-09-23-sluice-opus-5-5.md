# Plan: sluice-opus-5-5

## Goal

Sluice routes, meters and guards correctly on Opus 5.5, downshifts by effort
rather than by model, and its eval suite shows both on 5.5. Design:
`docs/specs/2026-09-23-sluice-opus-5-5.md`.

## Architecture

The channel is recorded by a tool call, `status.sh route <channel>`, because
5.5 stores prose between tool calls as a paraphrased thinking summary and tool
inputs verbatim. The meter and the Stop hook's entry check read that call
alongside the existing text anchors. The plan's `Model` mark becomes an
`Effort` mark; a task marked `Effort: low` is dispatched on the
`sluice-implementer-low` agent definition (`model: inherit`, `effort: low`),
which the installer places under `.claude/agents/` through the existing
`supporting` map. Everything the scripts learn lands inert first; one task
switches the skill's prose and retires the `Model` mark.

## Ground Rules

- Commit message convention: `<type>(<scope>): <subject>`, scope `sluice` for
  skill work and `cli` for installer work, subject lower case, no trailing full
  stop. No `Co-Authored-By` trailer, no tool footer, no session link.
- Test runner: `bun test` from the repo root. The full suite was green at
  1557 tests before Task 1.
- Scripts stay bash 3.2 compatible and depend on nothing beyond `jq` and
  `git`, as the existing scripts do. No new dependency in `package.json`.
- Prose follows the files it lands in: no em dashes, comments say why.
- Tests assert on what a caller observes: exit codes, stdout, files written.
  Expected values are written by hand, never produced by running the code
  under test.
- The route marker regex is `(^|[[:space:]/])status\.sh[[:space:]]+route[[:space:]]+(fast|main|deep)([[:space:]]|$)`,
  identical in `run-stats.sh` and `stop-guard.sh`. It requires the script to be
  invoked, so a quoted mention (`grep 'status.sh route deep'`) does not match.
- Eval runs use `--model claude-opus-5-5` and every invocation carries
  `--max-cost-usd`, with the sum across all runs in this plan at most 100.
