# Design: sluice on Opus 5.5

## Goal

Sluice routes, meters and guards correctly when the session model is Opus 5.5,
and the eval suite can show it. Source: "Prompting Claude Opus 5.5"
(platform.claude.com, build-with-claude/prompt-engineering).

## What 5.5 changed for sluice

1. **Some text between tool calls is no longer a `text` block.** 5.5 can
   return it as a progress-update `thinking` block holding a paraphrased
   summary, and the literal words then appear nowhere in the transcript. In the
   session that wrote this design, 3 of 12 assistant notes landed that way, all
   of them unprompted notes written mid-turn; the turn-opening "Deep channel"
   announcement and notes written in reply to the harness's "say what you're
   doing" reminder stayed `text`. One session does not settle the rule. What it
   does show is that an announcement made mid-turn can vanish, and escalation
   ("this fast task needs a new interface, now main") is always mid-turn: that
   is the trail `run-stats.sh` (`announces`), the `stop-guard.sh` entry check
   and the `announces-*-channel` graders can lose.
2. **Early stops are more frequent and more varied.** 5.5 ends turns with
   progress reports. The doc names four kinds and says naming each one is what
   works: a summary that announces the next step without taking it, an offer to
   carry on unless the user prefers otherwise, a list of decisions none of which
   blocks the rest, and stopping to report because a milestone landed. A
   continuation message works best when it names the open items.
3. **Effort, not model, is the cost lever.** On 5.5, `low` comes close to
   `medium` on coding at much lower cost, and `medium` matches Opus 5 at `high`.
4. **Time signals speed up multi-agent work.** An `elapsed / budget` line, or
   one sentence saying time matters, makes agent teams finish sooner. Unmeasured
   for sluice.

## Decisions

### D1. The channel is recorded by a tool call

`status.sh route <fast|main|deep>` prints `sluice: <channel> channel` and exits
0. It writes no state: its job is to put the channel into the transcript
verbatim, because tool inputs are stored as written and prose between tool
calls is not. `bypass` is refused (exit 4), since bypass announces nothing.

SKILL.md: the announcement is still said for the partner, and the route call
rides in the same message. Escalating is another route call.

`run-stats.sh` and the `stop-guard.sh` entry check (the copy kept in step by
hand) treat a Bash `tool_use` whose command runs `status.sh route <channel>` as
an announcement, and take the channel from it. The text anchors stay, because a
text-only message (main's shape agreement, a stop) is still a `text` block.

### D2. Name the four early stops

The "run never ends a turn" bullet in `references/deep-channel.md` names all
four kinds, plus the stops that are wanted (the two stops, `blocked`, the
handback). SKILL.md's Stop-hook paragraph gets one clause pointing at them.

### D3. The Stop hook names the open tasks

The refusal reason lists each open task as `T<id> <name>` (control bytes
stripped, as the topic already is) and adds: if one is blocked, mark it and say
what is blocking it.

### D4. Downshift by effort, not by model

The plan field `**Model:**` becomes `**Effort:** low, <why the work is
mechanical>`. Same disqualifiers as today: `Flips` and tier-3 tasks may not
carry it, and `plan.sh validate` errors on them. A plan still carrying
`**Model:**` gets a validate error naming `Effort`. `status.sh task --model` and
`preflight --model` become `--effort`; `run.json` stores `effort`. Reviewers
never run below the effort of the task they review.

Setting a subagent's effort needs an agent definition: the Agent tool takes
`model` but no effort, and a definition's frontmatter carries `effort:`. So
sluice ships `agents/sluice-implementer-low.md` (`model: inherit`,
`effort: low`), and the dispatch brief goes out on that `subagent_type` for a
task marked `Effort: low`. Unmarked tasks go out as today, on the session's
model and effort.

The installer already carries this: `install.claude.supporting` maps a source
file to a target path and uninstall removes it. The one installer change is that
the claude adapter's bundle loop also writes every fetched file under the
bundleRoot, so a supporting file would land twice; the loop skips supporting
sources the way it skips the prompt.

### D5. Fix the blocks-on-a-real-decision prompt

Its `expected_outcome` says Task 2 lands and Task 3 is blocked. The graders and
the README say Tasks 2 and 3 land and Task 4 is blocked. The prompt is wrong.

### D6. Evals

Existing graders change first:

- `announces-{fast,main,deep}-channel` accept either anchor: the route call in
  a Bash input, or the text anchor. The two fast cases lose the unanchored
  `fast channel` pattern the README already flags.

New cases, each with a small fixture in the style of the current ones:

| Case | Pins | Key graders |
|---|---|---|
| `announcement-reaches-the-ledger` | The channel is recorded where the meter reads it, including an escalation made mid-turn | Bash `status.sh route fast` used; Bash `status.sh route main` used after it; source changed |
| `deep-run-survives-a-milestone` | Six tasks, two waves; no stop after wave 1 | 6 done in `run.json`; Stop-hook reason absent from trace (kept the rule vs was caught); final message is a handback |
| `deep-run-decides-a-non-blocking-choice` | An open choice that blocks nothing is decided, recorded and passed | all done; 0 blocked; record carries the choice; final message is not a decision list |
| `deep-run-waits-for-a-running-agent` | A dispatched implementer still running is waited for | all done; `T<n>:` labelled Agent dispatch; handback only after the result |
| `fast-reads-the-unmentioned-convention` | The convention lives in a file the prompt never names | the flag lands in the registry table the repo's CONTRIBUTING names |
| `deep-run-fans-out` | Time-budget A/B | all done; three Agent dispatches in one message; `durationSeconds` compared across two skill variants (with and without the time sentence in the brief) |

`deep-run-fans-out` is a measurement, not a rule: the time sentence goes into
the brief only if the A/B shows it is faster at the same score.

Baseline: the whole suite with `--model claude-opus-5-5`. `claude plugin eval`
has no effort flag, so the effort sweep the doc suggests cannot be run through
it; the baseline runs at the default effort only.

Unit tests (bun, `tests/sluice-*.test.ts`) pin the script side: `route`
accepts and refuses; `run-stats.sh` finds the channel in a transcript where the
announcement is a thinking block and the route call is a Bash input; the entry
check treats that session as routed; the refusal names open tasks; `validate`
enforces the `Effort` rules.

## Not changing

- No thinking instructions or reasoning-in-response instructions exist in the
  skill, so nothing to remove there.
- The one-refusal-per-turn Stop hook is inside the doc's cap of two or three
  automatic continuations.

## Resolved at sign-off

1. **Agent files (D4):** installed through `supporting`, with the bundle-loop
   fix above.
2. **Eval spend:** iterate at `--runs 1 --ablation none`, then one full pass;
   every run carries `--max-cost-usd` and the total stays at or under 100.
